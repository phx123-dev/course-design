## 1 项目概述

### 1.1 项目背景与意义

随着智能制造战略的深入推进，智能车间中数控机床、工业机器人、AGV 等关键设备日益密集。设备一旦发生故障，轻则造成单机停机，重则导致整条产线停产，带来巨大的时间与经济损失。传统的"事后维修 + 定期点检"模式存在响应慢、过度维修、漏检等问题，难以满足现代智能车间对高可靠、低成本、快响应运维的要求。

与此同时，大语言模型（LLM）及其衍生的智能体（Agent）、检索增强生成（RAG）技术快速发展，为"人—机"自然交互和知识密集型决策提供了新的可能。本课题将大模型多智能体与机器学习预测、工业数据、设备知识库相结合，构建面向智能车间的故障诊断与预测性维护辅助系统，形成"数据接入—智能诊断—预测预警—维护决策—人机交互"的完整技术闭环，具有较强的工程应用价值与研究意义。

### 1.2 建设目标

总体目标：构建一套面向智能车间关键设备（以轴承/旋转机械、数控机床等为典型对象）的运维辅助系统，实现设备状态实时监测、故障智能诊断、剩余寿命/故障概率预测、维护工单自动生成与对话式人机交互，形成"看得见、判得准、防得住、管得省"的设备健康管理闭环。

具体目标与关键技术指标：

| 序号 | 目标 | 说明 |
| --- | --- | --- |
| 1 | 设备数据接入与实时监控 | 接入公开数据集及模拟传感器数据，实现设备运行状态实时监测与可视化 |
| 2 | 机器学习故障预测 | 训练故障诊断/预测模型，输出故障概率与剩余寿命预警，诊断准确率 ≥90% |
| 3 | 大模型多智能体智能诊断 | 多个 Agent 协作（数据读取→知识检索→诊断推理→方案生成），单次问答/诊断 ≤10s |
| 4 | RAG 知识库支撑 | 构建设备手册、维修经验、工艺规范知识库，为诊断提供可溯源依据 |
| 5 | 维护决策与工单管理 | 自动生成点检计划、维护工单、备件与处置建议 |
| 6 | 对话式人机交互 | 自然语言问诊，支持"问—诊—答—派单"一体化操作 |
| 7 | 报告与演示交付 | 可运行 Web 系统、设计方案文档及演示材料 |

### 3.2 用户角色与权限

系统设三类角色：维护工程师（engineer）为系统主要使用者，负责诊断、点检与维修；车间管理员（manager）掌握整体设备健康与运维绩效；系统管理员（admin）维护设备台账、知识库与用户权限。语料上传仅 engineer 与 admin 可用，语料删除、台账增删改仅 admin 可用，流引擎启停权限按角色区分。

### 3.3 范围边界

1. 数据边界：传感器数据采用 Python 模拟振动信号生成器合成（按轴承特征频率 BPFI/BPFO/BSF 构造冲击信号），非企业真实数据；知识库语料为依据公开资料整理的设备手册/维修案例/SOP 文本；系统提供公开 CWRU 数据集的可选补充加载脚本，保证课程设计可复现与演示稳定。
2. 运行边界：不配置大模型 API Key 时系统自动进入离线模拟模式（规则+模板+知识检索+ML 预测结果填充），保证演示不中断；架构上支持后续接入真实产线数据源。

## 4 总体方案与技术路线

### 4.1 总体架构

系统采用 B/S 五层架构：展示层（前端 Web：登录、健康看板、设备详情、智能诊断对话、工单、知识库）；应用层（FastAPI 后端：认证鉴权、设备/工单/知识库服务、对话服务、数据转发）；智能层（多智能体编排、RAG 检索、机器学习预测模型、提示词）；数据层（SQLite 关系库存储台账/时序/工单，知识块向量入库）；数据源（模拟数据生成器、公开数据集、可选实训数据）。

核心数据流：数据源→数据接入→时序数据表；历史数据→特征工程→模型训练→模型库；用户问诊→多智能体工作流（读取实时数据+检索知识库+调用预测模型）→诊断结果与工单→前端展示。

### 4.2 技术栈选型

| 层次 | 技术选型 |
| --- | --- |
| 前端 | Vue3 免构建 SPA（本地 CDN 库）+ ECharts + Element Plus |
| 后端 | Python 3.13 + FastAPI（RESTful API）+ WebSocket |
| 智能层 | 自研状态图多智能体编排（5 节点）+ DeepSeek API（OpenAI 兼容）+ 自研 numpy 向量检索（RAG）；编排器/向量库留可替换位 |
| 机器学习 | Scikit-learn + XGBoost（故障分类），NumPy/Pandas 特征工程，孤立森林/3σ 异常，RUL 退化拟合 |
| 数据层 | SQLite + SQLAlchemy ORM（13 张表），知识块向量 JSON 存储 |
| 工程化 | Git + GitHub 版本管理、requirements.txt 依赖管理、Python 虚拟环境 |

### 4.3 数据资源方案

| 数据集 | 内容 | 用途 | 获取方式 |
| --- | --- | --- | --- |
| 自建模拟数据 | 合成传感器时序 + 故障注入 + 随机噪声 | 系统联调、离线演示兜底 | Python 生成（确定性 seed） |
| CWRU 轴承数据集 | 正常/内圈/外圈/滚动体故障振动信号 | 故障分类模型训练与验证 | 公开免费下载，可选补充 |
| NASA IMS 轴承退化数据集 | 全寿命振动时序数据 | 退化趋势分析与剩余寿命预测 | 公开免费下载（进阶） |
| 知识库语料 | 设备手册、SOP、维修案例 | RAG 知识增强 | 公开资料整理 + 自建（25 篇 md） |

### 4.4 关键技术路线

1. 多智能体工作流：自研状态图编排器实现"意图识别→数据读取→知识检索→诊断推理→决策方案"五节点流水线，支持条件分支（澄清/咨询/诊断）与离线双模运行，关键节点调用工具（查库、查时序、调预测模型、检索向量库），诊断结论以结构化 JSON 输出并全程留痕。
2. RAG 检索增强：语料切分（chunk）→ jieba 分词 + 特征哈希向量化（1024 维）→ numpy 余弦检索 Top-K + 关键词混合加权 → 拼装上下文生成，检索结果携带来源与相似度供溯源。
3. 机器学习预测：对振动时序提取时域特征（均值、方差、峰值、峭度、均方根等）与频域特征（FFT 主频、频带能量等）；XGBoost/随机森林四分类；孤立森林 + 3σ 阈值异常预警；退化趋势线性外推估计剩余寿命。
4. 双模运行：配置 DeepSeek API Key 时走大模型模式；未配置时自动切换离线模拟模式，两种模式走相同的多智能体编排流程，保证演示稳定。

### 8.3 过程质量

全程使用 git 小步提交，提交说明遵循"<type>: <简述>"规范（init/docs/data/feat/test/fix），一个里程碑一个（或少量）提交；每阶段更新 prompt 会话日志（session-*.json）作为过程档案；AI 使用情况在报告中如实披露（所用工具、关键 prompt 策略、AI 出错案例及纠正过程）。

## 9 风险分析与应对

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 大模型 API 额度/稳定性受限 | 智能诊断不可用 | 配置多模型切换；关键路径做规则/模板兜底（离线双模） |
| 公开数据集格式复杂/下载受限 | 模型训练受阻 | 优先用 CWRU；模拟数据生成器兜底 |
| 多智能体流程不稳定/输出不可控 | 诊断质量下降 | 状态图强约束、输出 JSON 校验、人工确认节点、简化工作流 |
| 知识库语料不足 | RAG 检索效果差 | 自建模拟案例库 + 公开手册整理；检索阈值与重排调优 |
| 时间紧张、任务量大 | 延期交付 | 模块优先级排序，先核心闭环再优化 |
| 前后端联调问题 | 系统演示受阻 | 接口先行约定（OpenAPI），前后端并行开发 |

### 10.2 验收标准

1. 系统可运行：一键脚本可启动，前端走通"登录—看板—诊断—派单—报告"完整业务流程；
2. 可测试：自带自动化测试全部通过；
3. 可演示：无 API Key/无模型文件时离线降级模式仍可完整演示；
4. 可溯源：诊断结论附知识引用与数据证据，全链路 trace 入库；
5. 可复现：信号合成、向量化、训练全部确定性（固定 seed）。
