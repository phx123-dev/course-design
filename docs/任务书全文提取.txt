制造智能技术课程设计任务书
1. 课程设计目标
（1）能够运用人工智能原理，分析制造环节特定问题，并利用现有资源提出解 决方案并设计实施。（支撑毕业要求指标点 3.2）
（2）能够选择与使用恰当的人工智能模型、计算资源、数据，针对制造工程特 定环节的问题进行分析、模拟和预测。（支撑毕业要求指标点 5.2）
（3）能够根据准确表述，清晰表达制造工程问题解决过程中所涉及的智能技 术、设计方法和设计方案。（支撑毕业要求指标点 10.1）
2. 选题要求
自主选题，运用 vibe coding 方法开发面向制造/工业场景的智能应用，并要求： （1）场景：应用场景须为制造/工业环节（如设计、生产、质量控制、设备运 维、物流仓储、生产管理等）的智能化应用，具有真实业务感；鼓励结合实习见 闻、企业真题、公开工业数据集，不要求真实企业数据。日常生活场景（如影视推 荐、穿搭助手等）不予通过。 （2）内容：运用《制造智能技术》课程所学至少 3 章相关技术手段。 （3）架构：实现完整 B/S 或 C/S 架构的可运行 demo，包括但不限于：①前端 UI，能走通完整业务流程；②后端服务（API 或服务层），承载业务逻辑；③数据 库；④算法模块，即满足第（2）条的至少 3 个技术方向功能。
3. 课程设计内容
（1）vibe coding 方法学习：提示词工程（任务拆解、约束说明、验收标准）、 上下文工程（项目规则文件、让 AI 先读代码再改）、规格驱动开发（需求文档→AI 制定计划→分步实现→逐步验收）、AI 代码的自动化测试与人工审查、调试与人工 接管策略（回滚、缩小改动、最小复现）。
（2）代码管理相关：git 版本控制。 （3）选题：提交选题（含技术方向映射表、系统架构草图、数据来源）。 （4）数据资源整理：完成数据集的收集、清洗、处理与入库。 （5）系统开发与集成调试：运用 vibe coding 完成后端服务、数据库、前端界

4. 具体要求
（1）选题申报：通过第 1 阶段 vibe coding 学习和调研后，自行选题，每人 1 题， 群内接龙提交选题，后提交选题不允许与已提交选题重复。
（2）过程档案：全程使用 git 管理，小步提交并撰写有意义的提交说明；保留 prompt/会话日志；微信群内截图打卡。
（3）技术方向覆盖：答辩时须说明每个技术方向在系统中的实际作用；仅装饰 性引入不计入覆盖。
（4）架构完整：评分侧重架构完整与业务闭环而非功能数量。 （5）报告与答辩：设计报告须涵盖背景调研（研究意义）、方案设计、数据资 源构建、系统实现（前端/后端/数据库/各算法模块）、测试与集成调试、AI 使用披 露（所用工具、关键 prompt 策略、AI 出错案例及纠正过程）、总结展望等章节。参 照报告内容制作答辩 PPT，答辩自述 3 分钟、问答 7 分钟；问答环节教师将随机指 定 1–2 处 AI 生成的代码段，学生须现场讲解其作用与逻辑。 （6）提交物清单：①代码仓库（git，含完整提交历史，运行脚本，readme 文 档）；②需求规格说明书；③设计报告；④3 分钟演示视频；⑤过程档案（prompt 日志、打卡记录）。
5. 注意事项
（1）允许且鼓励全程使用 AI 编程工具完成开发，但须在报告中如实披露所用 工具与关键 prompt 策略。
（2）设计报告可以利用 AI 梳理内容逻辑，但不要将 AI 生成内容直接作为报告 内容。确保自己熟知报告中所有内容，切忌将自己不懂的内容写入报告。答辩中如 果发现有 AI 生成，而自己不能说清的地方，将大幅影响成绩，甚至不及格。
（3）项目须通过自带的自动化测试；禁止直接提交他人完整项目，或 AI 一键 生成后未经理解消化的成果。

7. 考核与成绩评定
考核成绩由三部分组成：过程考核 30%、成果考核 50%、答辩评价 20%。过程 考核依据选题与方案设计过程及 vibe coding 过程档案（git 记录、微信打卡）；成果 考核由设计说明书（25%）和程序（25%）两部分组成，程序依据架构完整性、至 少 3 个技术方向覆盖、功能完成度与代码测试质量考核；答辩评价依据方案表达与 随机代码段讲解。
