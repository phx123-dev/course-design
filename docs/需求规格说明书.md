# 需求规格说明书

> 基于大模型多智能体的智能车间设备故障诊断与预测性维护系统
> 版本：v1.0 · 2026-09-11 · 智能制造工程专业课程设计

## 1. 引言

### 1.1 编写目的

本文档定义"基于大模型多智能体的智能车间设备故障诊断与预测性维护系统"的功能需求、接口需求、数据需求与非功能需求，作为系统开发、测试与验收的依据。每个功能需求均给出可测试的验收标准，验收标准与自动化测试断言一一对应（见测试章节）。

### 1.2 术语

| 术语 | 说明 |
| --- | --- |
| PHM | 故障预测与健康管理（Prognostics and Health Management） |
| RUL | 剩余使用寿命（Remaining Useful Life） |
| RAG | 检索增强生成（Retrieval-Augmented Generation） |
| BPFI/BPFO/BSF | 轴承内圈/外圈/滚动体故障特征频率 |
| SSE | 服务器推送事件（Server-Sent Events），用于流式回复 |
| 离线模拟模式 | 无大模型 API Key 时，智能层以规则+模板+ML+知识库运行的降级模式 |

## 2. 系统概述

面向智能车间关键设备（轴承/旋转机械、数控机床等），构建"**数据接入 → 实时监控 → 机器学习预测 → 多智能体诊断（RAG 知识增强）→ 维护工单闭环 → 对话式交互**"的运维辅助 B/S 系统。系统以模拟传感器数据与自建知识语料为数据底座（如实披露，非企业真实数据），架构上支持后续接入真实产线数据源。

## 4. 功能需求

### F1 用户登录与权限管理

- **描述**：基于角色的账号密码登录，令牌有效期 12 小时，接口按角色鉴权。
- **主流程**：输入账号密码 → 服务端校验 PBKDF2 哈希 → 签发令牌 → 进入看板。
- **异常流**：密码错误返回 401；无令牌/令牌过期访问接口返回 401；越权操作返回 403。
- **验收标准**：`test_auth.py` — 登录成功返回令牌与角色；错误密码 401；无令牌 401；engineer 写台账 403。

### F2 设备台账管理

- **描述**：设备基础信息（编号/名称/类型/位置/转速/负载/健康状态）增删改查。
- **验收标准**：`test_auth.py`（角色权限）与 e2e"设备台账列表"——列表返回 ≥6 台设备；编号唯一性校验（重复编号 400）。

### F3 数据接入与实时监控

- **描述**：流引擎按 1s 周期生成模拟传感器数据（振动 RMS/峰值/温度/转速），WebSocket 实时推送；支持故障注入演示（修改设备健康状态，流引擎立即产生对应故障信号）；波形按 (设备, 时刻) 确定性回放。
- **异常流**：WebSocket 断开自动切换 HTTP 轮询兜底；引擎异常不影响接口服务。
- **验收标准**：`test_signal_gen.py`（信号可复现/可区分）、e2e"实时数据快照"；注入故障后产生 3σ 预警（e2e 前手工冒烟 + `test_anomaly.py`）。

### F4 机器学习故障预测

- **描述**：对振动信号提取 14 维时域/频域特征；XGBoost/随机森林四分类（正常/内圈/外圈/滚动体）；输出类别概率、健康评分；孤立森林+3σ 异常预警；退化趋势线性外推估计 RUL。
- **验收标准**：`test_ml_predict.py` — 测试集准确率 ≥0.90；四类概率和为 1；故障样本分类正确；RUL 退化检测与小时数合理性。

### F5 大模型智能诊断

- **描述**：五节点多智能体编排（意图识别→数据读取→知识检索→诊断推理→决策方案），LLM 与离线双模运行；诊断结论结构化 JSON，含故障类型/置信度/原因/依据引用；全过程留痕（trace）。
- **验收标准**：`test_agents.py` — 事件序列完整；诊断结论与注入故障一致；依据非空；端到端耗时 ≤10s（e2e 断言）。

### F6 维护工单管理

- **描述**：工单创建（手动/诊断自动派单）、状态流转（待处理→进行中→已完成，记录时间戳）、筛选查询。
- **验收标准**：`test_workorders.py` — 状态流转合法、非法状态 422、diagnosis 来源工单携带诊断记录关联。

### F7 知识库管理（RAG）

- **描述**：语料上传/切分/特征哈希向量化入库；混合检索（向量余弦 0.7 + 关键词 Jaccard 0.3）；检索结果带来源与相似度；同文档去重。
- **验收标准**：`test_rag.py` — 切分块大小与字符定位一致；向量归一化与确定性；"内圈故障"查询命中内圈文档且排序正确。

### F8 对话式交互

- **描述**：自然语言问诊，SSE 流式回复（过程步骤可视化 + 打字机效果）；诊断回复附依据溯源卡片；支持一键生成工单。
- **验收标准**：`test_agents.py`（澄清/咨询/诊断三分支）+ e2e"SSE 事件序列完整/流式回复非空/依据溯源"。

### F9 报告与导出

- **描述**：单设备诊断报告（监测数据/预测/诊断结论/预警/工单）与运维周报（7 天统计）Markdown 导出。
- **验收标准**：`test_workorders.py` — 报告内容含标题结构与统计数据；e2e 两项导出检查。

## 5. 接口需求

### 5.2 WebSocket

`/ws/device/{id}?token=<令牌>`：每秒推送最新采样与新预警；无效令牌关闭连接（4401）。

### 5.3 SSE 事件流（POST /api/chat/messages）

`start → intent → data → retrieve → diagnose → plan → token* → done`，done 携带 `{reply, diagnostic_id, evidence[], diagnosis, plan, mode, latency_ms, trace[]}`。

## 6. 数据需求

13 张表（SQLite，SQLAlchemy ORM）：users / auth_tokens / equipment / sensor_samples / alarms / predictions / ml_models / work_orders / knowledge_docs / knowledge_chunks / chat_sessions / chat_messages / diagnostic_records。关键约定：

- 健康状态 0-3 与故障类别标签一一对应（0 正常 / 1 内圈 / 2 外圈 / 3 滚动体）；
- 波形不落库（确定性回放），sensor_samples 每设备滚动保留 20000 条；
- 知识块向量以 JSON 存储于 knowledge_chunks，支持内存矩阵检索。

## 7. 非功能需求

| 类别 | 指标 | 验证方式 |
| --- | --- | --- |
| 性能 | 单次问答/诊断 ≤10s；看板刷新 ≤5s | e2e 断言 latency_ms<10000 |
| 可用性 | 无 API Key/无模型文件时系统可降级运行 | 离线模式/available=false 设计 + 测试 |
| 安全性 | API Key 仅存服务端 .env（不入库不入前端）；接口统一鉴权；令牌存摘要 | 代码审查 + 401/403 测试 |
| 可扩展性 | 分层架构；编排器/向量库留 LangGraph/Chroma 可替换位 | 代码注释 + 方案设计 3.2 |
| 可追溯性 | 诊断结论附知识引用与数据证据，全链路 trace 入库 | test_agents 入库检查 |
| 可复现性 | 信号合成/向量化/训练全部确定性（固定 seed） | test_signal_gen/test_rag |

全部功能验收标准已由自动化测试覆盖并通过：后端单元/集成测试 8 个文件、前端挂载测试 16 项、e2e 全业务闭环 18 项，详见《设计报告》第 5 章测试与集成调试。
