## 第 1 章 背景调研（研究意义）

### 1.1 行业背景

智能制造战略推进下，车间内数控机床、工业机器人、AGV 等设备日益密集，设备可靠性直接决定产线产能与产品质量。设备故障具有突发性、隐蔽性、多因性等特点，传统"事后维修 + 定期点检"模式存在三大问题：

1. **响应慢**：故障发生后才发现，非计划停机损失大；
2. **过度维修**：按固定周期更换部件，健康部件被提前更换，浪费备件成本；
3. **漏检**：点检周期内发生的早期故障被错过，小隐患演变为大事故。

以滚动轴承为例，其在旋转机械故障中占比约 30%~40%，而内圈/外圈/滚动体等典型缺陷在振动信号中具有明确的特征频率（BPFI/BPFO/BSF），为数据驱动的智能诊断提供了物理基础。

### 1.2 技术背景

- **机器学习预测**：振动信号时域统计特征（RMS、峭度、波峰因子等）与频域特征（特征频带能量）结合随机森林/XGBoost，可对故障类型进行高精度分类；
- **大模型与智能体**：LLM 擅长自然语言理解与知识整合，但存在幻觉风险；RAG 将检索到的知识注入上下文，使生成内容有据可依；
- **多智能体编排**：将复杂诊断任务拆分为意图识别、数据读取、知识检索、诊断推理、决策方案等多个专职智能体，节点可控、过程可溯源，贴近工业可解释性要求。

### 1.3 课题意义

本课题将上述三大技术方向融合，构建"看得见、判得准、防得住、管得省"的设备健康管理闭环，覆盖了任务书要求的**大模型、机器学习、数据库**三个课程技术方向（另含工业物联网数据处理与 Web 可视化扩展方向），具有明确的工程应用价值。

## 第 3 章 数据资源构建

### 3.1 模拟振动信号（如实披露：非企业真实数据）

采用物理模型合成：正常信号 = 转频基波+谐波+白噪声；故障信号 = 正常分量 + 特征频率上的周期性指数衰减冲击串：

```
BPFI = fr·n/2·(1+d/D·cosφ)   BPFO = fr·n/2·(1-d/D·cosφ)   BSF = fr·D/(2d)·(1-(d/D·cosφ)²)
x_imp(t) = Σ A_k·e^{-β(t-kT)}·sin(2πf_n(t-kT))，T = 1/f_fault
```

- 6205 量级轴承参数（n=9、d=7.94mm、D=39mm），1750rpm 下 BPFI≈158Hz、BPFO≈104Hz、BSF≈68Hz；
- 采样率 12kHz（与 CWRU 一致），训练集 4 类 × 150 窗口（0.25s/3000 点），转速 ±2%、噪声 ±30% 抖动增强多样性；
- 内圈故障叠加转频幅度调制（频谱出现 fr 边带，与真实数据特征一致）；
- 全部随机量由 seed 控制，**结果可复现**；`scripts/load_cwru.py` 提供公开数据集可选加载。

### 3.2 知识库语料（自建 25 篇，公开资料整理）

| 类别 | 数量 | 内容 |
| --- | --- | --- |
| 故障知识 | 8 篇 | 内圈/外圈/滚动体/保持架故障特征与诊断、润滑不良、不平衡、不对中、特征频率计算公式 |
| 设备手册 | 6 篇 | 数控车床/加工中心/风机/输送机/磨床/AGV 维护手册 |
| 作业 SOP | 4 篇 | 振动检测、日常点检、主轴更换、润滑加注 |
| 维修案例 | 5 篇 | 内圈/外圈/滚动体/温度异常/润滑不良案例（含诊断过程与经验总结） |
| 通用规范 | 2 篇 | 预测性维护指南、工单与备件管理规范 |

入库流程：Markdown 按标题/段落切分为 200~400 字块（记录字符级定位）→ jieba 分词 → 特征哈希 1024 维 TF 向量 → 入库共 115 个检索块。

## 第 4 章 系统实现

### 4.1 前端（免构建 SPA）

- 七个页面：健康看板 / 设备监控 / 智能诊断 / 工单管理 / 知识库 / 设备台账 / 系统管理；
- 看板：统计卡片 + 健康分布饼图 + 24h 预警趋势 + 设备健康列表（5s 自动刷新）；
- 监控页：WebSocket 实时曲线（断开自动轮询兜底）+ 波形频谱（确定性回放）+ 故障注入演示 + 预测面板 + RUL 退化演示；
- 对话页：SSE 流式解析，多智能体过程步骤实时展示（意图→数据→检索→诊断→方案），打字机回复 + 依据溯源卡片 + 一键派单；
- 组件复用：health-tag / wo-status-tag / device-select / evidence-card 全局注册。

### 4.2 后端（FastAPI 分层）

`routers(API) → services(业务/算法) → db(数据层)`：

- 鉴权：PBKDF2 密码哈希 + 随机令牌（库存 SHA256 摘要）+ 角色依赖注入；
- 流引擎：单写线程，1s/条采样，波形确定性回放不落库，每设备滚动保留 2 万条；温度模型带一阶热惯性（故障后几秒缓慢爬升，更真实）；
- 异常预警：3σ（基线由正常工况统计）+ 孤立森林 + 温度超限，同类型去重。

### 4.3 数据库（13 表）

users / auth_tokens / equipment / sensor_samples / alarms / predictions / ml_models / work_orders / knowledge_docs / knowledge_chunks / chat_sessions / chat_messages / diagnostic_records。诊断记录表保存结论 JSON、依据 JSON、模式、耗时与节点 trace，实现全链路可溯源。

### 4.4 机器学习模块

- 特征工程（14 维）：时域 9 维（均值/标准差/RMS/峰值/峰峰值/波峰因子/峭度/偏度/方差）+ 频域 5 维（主频/主频幅值/BPFI·BPFO·BSF 特征频带能量，汉宁窗 FFT）；
- 训练：随机森林 vs XGBoost 对比，最优模型入库并登记（准确率 100%/95.8%）；xgboost 安装失败时自动降级 sklearn GradientBoosting（代码级 try/except）；
- 健康评分 = 100 × (p_normal + 0.5·p_outer + 0.2·p_inner + 0.15·p_ball)（按故障严重性加权）；
- RUL：健康指标 HI = 1-(rms-rms_n)/(rms_f-rms_n)，对近期 HI 序列按真实时间戳最小二乘拟合退化斜率，外推至失效阈值 HI=0.15，输出剩余小时数。

### 4.5 RAG 知识库模块

切分（标题感知，200~400 字/块，字符级定位）→ 特征哈希向量化（jieba 分词 + TF 权重 + L2 归一化）→ 内存矩阵检索（内积即余弦）→ 混合打分（0.7 余弦 + 0.3 关键词 Jaccard）→ 同文档去重 → 引用编号。全部确定性、离线可用。

### 4.6 多智能体模块（核心）

- **状态对象 AgentState**：贯穿五节点的共享状态，接口对齐 LangGraph State 思想；
- **节点**（纯函数）：意图识别（规则优先，诊断/咨询/澄清三分支）→ 数据读取（4 个工具：台账/时序/特征/ML 预测）→ 知识检索 → 诊断推理 → 决策方案；
- **LLM 模式**：DeepSeek（httpx 直调），角色化 System Prompt + JSON 输出约束（response_format=json_object）+ 四级 JSON 校验降级链（直接解析→正则提取→截断修复→离线兜底）；
- **离线模式**：诊断结论直接采用 ML 预测结果（置信度=模型概率），原因/处置从知识块抽取，字段与 LLM 模式完全一致；
- **可溯源**：每个节点记录模式/耗时/备注，诊断结论、依据引用、trace 全量入库。

### 6.2 关键 prompt 策略

1. **规格驱动开发**：先定《需求规格说明书》与验收标准，再分里程碑实现，每个里程碑"可运行+可测试"才提交（对应任务书 vibe coding 方法）；
2. **JSON schema 约束**：为诊断/方案 Agent 编写角色化 System Prompt，强约束"只引用提供的 [编号] 材料、只输出 JSON、数据不足时置信度取 0.5 以下"，配合四级解析降级链兜底模型输出不稳定；
3. **验收标准先行**：每个功能需求在规格文档中绑定测试断言，AI 生成代码后立即运行测试验证（对应"AI 代码的自动化测试与人工审查"）；
4. **小步提交 + 回滚**：一里程碑一提交，出错时可精确定位回滚（对应"调试与人工接管策略"）。

### 6.3 AI 出错案例及纠正过程（真实记录）

| # | AI 生成的错误 | 发现方式 | 纠正过程 |
| --- | --- | --- | --- |
| 1 | numpy 布尔索引副本 bug：`sig[mask][:n] += x` 对副本赋值，冲击信号静默丢失，导致故障信号 RMS 反而低于正常信号 | 单元测试断言"故障能量显著高于正常"失败 | 改用索引数组 `sig[idx] += x` 原地累加，并在代码注释标明该 numpy 陷阱 |
| 2 | pandas `groupby.apply` 子采样后分组列 label 丢失，训练代码 KeyError | 训练脚本首次运行即崩溃 | 改为按组采样索引后 `df.loc[idx]` 取值 |
| 3 | RUL 拟合按"采样序号"而非真实时间戳，压缩时间尺度的数据给出荒谬的小时数 | 测试断言 RUL 应为小时量级失败 | 拟合改用真实时间戳（小时），不同采样间隔下斜率物理一致 |
| 4 | JSON 截断修复补全括号顺序错误（`}` 先于 `]`），修复后的 JSON 仍解析失败 | 降级链单元测试失败 | 用栈记录开括号并按逆序闭合 |
| 5 | 前端组件注册顺序错误（app.js 先于 pages2.js 执行，注册时 Pages 未定义），页面渲染为未解析自定义元素 | jsdom 挂载测试发现 `<page-dashboard>` 未渲染 | 调整为 components → pages → app 的脚本加载顺序（与成熟项目约定一致） |
| 6 | 看板路由漏导入统一响应包装函数，接口 500 | e2e 全链路测试在最后一步报错 | 补导入并增加"路由变更后必须跑 e2e"的检查习惯 |
| 7 | 温度模型无热惯性且正常基线 64℃ 贴近 70℃ 阈值，演示中误报 | 手工冒烟观察数据不合理 | 改为分段目标温度 + 一阶热惯性模型，正常 48℃、故障后几秒爬升过阈值，物理更合理 |
| 8 | RAG 检索结果前几名被同一文档的多个 chunk 占据，引用来源单一 | 检索质量手工检查 | 增加同文档去重（每文档仅保留最高分块） |

## 第 7 章 总结与展望

### 7.1 完成情况

对照任务书要求全部达成：① 工业场景（设备运维）✓；② 三大课程技术方向真实参与业务计算 ✓（映射表见 2.4）；③ 完整 B/S 可运行 demo（前端 7 页面走通业务闭环 + 后端 API + 13 表数据库 + 智能层算法模块）✓；④ git 10 个里程碑小步提交 + prompt 会话日志过程档案 ✓；⑤ 自带自动化测试（9 个测试文件 + e2e 18 项）全绿 ✓；⑥ 设计报告含 AI 使用披露 ✓。

### 7.2 不足

- 数据为模拟信号，与真实产线数据仍有差距（振动传递路径、多故障耦合未建模）；
- 离线模式诊断深度有限（依赖模板与检索质量）；
- LLM 模式响应时长依赖外部 API 波动，极端情况下存在超时风险。

### 7.3 展望

1. 接入真实产线数据源（MQTT/OPC UA），替换模拟生成器；
2. 引入 bge-small-zh 等语义 Embedding 替换特征哈希，提升检索语义理解；
3. 编排器迁移 LangGraph，支持更复杂的重试/人工确认分支；
4. 增加多故障复合诊断与退化曲线深度学习方法（LSTM）；
